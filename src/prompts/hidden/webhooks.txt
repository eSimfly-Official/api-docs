# eSIMfly Business API — Webhooks (PUT/GET /webhooks) — prompt for AI coding assistants

TASK: configure the eSIMfly webhook once and implement a secure receiver, so pending orders
(e.g. Japan/KDDI, 1–5 min provisioning) complete without polling.

COMMON RULES (apply to every eSIMfly request)
- Base URL: https://esimfly.net/api/v1/business
- Headers on every call: RT-AccessCode (esf_...), RT-RequestID (fresh UUID v4 per request; reuse -> 400 DUPLICATE_REQUEST),
  RT-Timestamp (ms since epoch; >5 min old -> 401 INVALID_TIMESTAMP),
  RT-Signature = UPPERCASE hex HMAC-SHA256(secretKey, timestamp + requestId + accessCode + rawBody).
  rawBody = "" for GET; for POST/PUT sign the exact body string you send, with Content-Type: application/json.
- Keep access code + secret key server-side in env vars. Never ship them to a browser or mobile app.
- Responses: { success: true, ... } or { success: false, error|message, code }. Branch on `success` and `code`.
- Rate limits per API key (defaults): 60/minute, 1,000/hour, 10,000/day -> RATE_LIMIT_EXCEEDED. Pace bulk work at <= 1 req/s.
- Read `currency` from responses (USD | IQD | EUR for enterprise). Never hard-code it. IQD amounts are integers.
- Package codes are opaque strings: store and send back verbatim, never parse or prefix them.
- Full multi-endpoint prompt: https://docs.esimfly.net/llm/esimfly-api-full-prompt.txt

CONFIGURE (one-time, or from an admin screen)
  PUT https://esimfly.net/api/v1/business/webhooks
  Body: { "webhook_url": "https://our-server.com/api/esimfly/webhook", "events": ["esim.provisioned"] }
  -> { success: true, webhook: { url, secret: "whsec_...", events }, note }
  SAVE `secret` in a secure secret store — it is shown once. (Also configurable in the dashboard, or per
  order with "callbackUrl" in POST /esims/order, which overrides the default URL for that order.)
  GET https://esimfly.net/api/v1/business/webhooks -> { success, webhook: { url, events, api_key_name },
      available_events: [{ event, description }], recent_deliveries: [{ id, event, order_reference, status, attempts, last_attempt, delivered_at }] }

DELIVERY (eSIMfly -> us)
  POST <webhook_url>, Content-Type: application/json, User-Agent: eSIMfly-Webhook/1.0
  Headers: X-Webhook-Event ("esim.provisioned"), X-Webhook-Signature ("sha256=<hex>"), X-Webhook-Timestamp (ISO), X-Webhook-Id (unique delivery id)
  Body: { "event": "esim.provisioned", "timestamp": "...", "data": { order_reference, iccid, qr_code_url (base64 data URL),
          lpa_string, direct_apple_install_url, direct_android_install_url, package_name } }
  Retries if we do not answer 2xx: immediate, 10 s, 30 s, 2 min, 10 min; then marked failed (visible in recent_deliveries).

RECEIVER — implement exactly
1. Read the RAW request body bytes (disable JSON body parsing on this route).
2. expected = "sha256=" + hex(HMAC-SHA256(secret, rawBody)); compare with X-Webhook-Signature using a
   constant-time comparison. Mismatch or missing header -> 401, do nothing else.
3. Dedupe: store X-Webhook-Id (fallback data.order_reference + event) with a unique constraint; if already
   seen -> respond 200 immediately.
4. Enqueue the payload and respond 200 within 10 seconds; do the work in a background job.
5. Job: find our order by data.order_reference; save iccid, lpa_string, direct_apple_install_url,
   direct_android_install_url; render QR from lpa_string (do not store the base64 image); set status
   completed; notify the customer.
6. If the order is unknown (race with our own order insert), retry the job a few times before alerting.
7. Keep the bounded polling fallback (GET /esims/order?orderReference=…, every 15–30 s, max ~10 min) for
   the rare case the webhook never arrives; make it stop as soon as the webhook completes the order.
8. Use HTTPS, and do not put the secret in logs or client code.

DELIVERABLE: setWebhook()/getWebhook() in the shared client, the raw-body receiver with signature check
and dedupe table, the background completion job, and an admin page showing recent_deliveries.
